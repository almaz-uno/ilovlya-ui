== [3.9.0] - 2026-10-24

.Changed
- The Flatpak uses the supported org.freedesktop.Platform 25.08 runtime instead of the end-of-life 24.08, with libmpv 0.40 (#139)

.Fixed
- Video plays smoothly on Linux under X11 and XWayland: the player draws it on the GPU again instead of in software, which showed only about every other frame on NVIDIA machines (#142)
- The Flatpak draws on the GPU on NVIDIA machines instead of in software: it no longer pins the EGL driver to Mesa nor lists Vulkan drivers without NVIDIA (#141)
- "Clean stale downloaded media" no longer stops silently at a file whose recording is not stored locally: such a file is kept and the cleanup goes on; the result, or an unexpected failure, is always shown, and the counters are updated either way (#148)
- With "Download while playing" on, a playback whose server stops sending without closing the connection no longer stays at 0% until the player is reopened: a request with no answer or no byte for 15 s is retried from the byte it reached, and a seek moves the download at once even while the server is silent (#144)
- While a playback download's server does not answer, the progress line under the player says so and how long the server has not answered, instead of a frozen speed and time remaining. A server that answers each retry with a portion and falls silent again counts as not answering, from when it stopped, until bytes have flowed for 5 s; so does one that brings less than 64 KiB in 15 s. A stalled transfer's speed decays, and no time remaining is shown while no bytes arrive (#144)
- A player whose source failed to open — the local address gave up on the server, or lost its connections while the application was in the background — opens it again at the saved position once the server answers, instead of staying at 0:00 (#144)
- On iOS, the time the application spent suspended in the background no longer counts as the server not answering: back in front, the progress line does not report a silent server, and a failure streak is not given up for time spent away; the transfer reconnects at once, and a server that is in fact silent is still reported after 15 s in front (#156)
- Count messages use the correct singular and plural forms in English and Russian, including cleanup results and file and recording totals (#151)
- On the server, adding a recording again keeps its saved duration and thumbnail when the new information is empty (ilovlya#47)
- Parallel additions that resolve to the same server download no longer start duplicate downloads or race over a shared temporary file (ilovlya#47)
- The Telegram bot no longer asks to choose media after successfully adding the only attachment or link (ilovlya#47)

== [3.8.0] - 2026-10-21

Playing a recording from its own download: with "Download while playing" on, the
file is fetched from the server once and played from while it arrives.

.Added
- Playback from the file being downloaded: one transfer instead of a stream and a download side by side, and no switch, reopening or message when the download completes
- Seeking beyond what has arrived, and files whose index sits at the end, are served by moving the download to where the player reads
- A playback download interrupted by closing the application resumes from what was stored the next time the recording is played
- On iOS, a playback paused in the background continues on return: the local address the player reads from stops listening while the application is suspended and listens again, on the same address, when it is back

.Changed
- The description of "Download while playing" says what it now does
- A paused playback download gives way to the explicit download button, which starts its own download
- The details under the player — when the recording was created, what is playing, its size and the player's technical state — sit in a "Details" section, collapsed when the player opens
- "Playing from" shows the server's URL while the file arrives and the local file once it has, not the local address the player reads from

.Removed
- The setting "Show additional technical info": the player's technical state is now always in the "Details" section

.Fixed
- A server outage during playback no longer ends the recording: the player keeps the position, says the playback was interrupted, and continues from there once the server is back — instead of marking the recording watched, or starting it from the beginning on play
- The position is no longer set to zero on the server at the start of every playback
- After the media is cleaned, the recording's screen no longer shows its download as complete
- Long items of the list's menu wrap instead of running past the menu's edge

== [3.7.0 Glauconite] - 2026-10-06

Casting a recording to a television through the television's browser. Casting
needs a server that provides `/api/tv`.

.Added
- Cast to TV on a recording's details screen, offered when the server holds a ready download
- Pairing with the code shown at `/tv` in the television's browser, typed or scanned as a QR code on Android and iOS
- Control while casting with the recording's own player: play/pause, skips and the progress bar act on the television; the cast button stops casting, handing playback back to the phone at the frame the television showed, or disconnects the television
- Position watched on the television is stored like local playback, so the recording resumes where it was left
- Control on the television itself: the video's own controls and the remote's OK, play/pause and arrow keys

== Version Format

This project uses https://semver.org/[Semantic Versioning]:

.Version Numbers
- *MAJOR* version for incompatible API changes
- *MINOR* version for backwards-compatible functionality additions
- *PATCH* version for backwards-compatible bug fixes

.Release Types
- *[Unreleased]* - Changes in development but not yet released
- *[X.Y.Z]* - Released versions with full feature sets
- *[X.Y.Z-alpha/beta/rc]* - Pre-release versions for testing

== Contributing

When adding entries to this changelog:

.Guidelines
- Add new unreleased changes under the `[Unreleased]` section
- Follow the format: Added, Changed, Deprecated, Removed, Fixed, Security
- Use present tense for change descriptions
- Include issue/PR numbers when relevant
- Move unreleased changes to a new version section when releasing

.Categories
- *Added* for new features
- *Changed* for changes in existing functionality
- *Deprecated* for soon-to-be removed features
- *Removed* for now removed features
- *Fixed* for any bug fixes
- *Security* for vulnerability fixes
